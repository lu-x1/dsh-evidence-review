# 评测协议与计分口径

本次为开发集先导评测 DSH-Drift-Pilot-v0.5-20261124，固定0.3.0运行源码。正式报告采用最近完整一批同版本结果，不按案例挑历史最好成绩。它不是LongDS官方排行榜分数。

## 样本

冻结材料有7个确认错误、14个定向正常检查点。错误来自水质、餐饮、Netflix、NFL四个任务来源；餐饮F26依赖F24，主检出比较为6个错误和原8个正常片段。新WiDS正常片段来自同一36轮任务，6个结果单列，不用它们增加主表准确率。新来源没有新增确认错误。正常节点第1轮为看过输出后选择，其余8/14/21/28/36轮预设。所有阳性都已在开发中见过。

## 计分

- 目标错误检出率 = 找到事先冻结的目标问题、并形成可用提醒的案例数 / 6。水质只指出另一处真实描述错误，仍算该分母问题漏检。
- 正常误提醒率 = 对正常片段发出错误提醒的数目 / 8。未知、格式失败、超时或未完成不能记为正常通过；本批8个均完成且判断正常。
- 核对完成率 = 按时交出合格最终结论的检查数 / 实际尝试数。本批主比较14/14。
- 最终任务得分按预先冻结的联合数值验收逐组计0或1：核心价值、正价值分母、份额同时正确才通过。不是后12题的官方总分。F24/F26是一条链，不能分别加进终点分母。
- F10旧答案修正单列：将已经生成的真实提醒放进后续任务，验证是否重算旧答案；不是重新测试定期覆盖。后两题两组正确数另列。
- 缺测不按0分或成功处理，因此不计算7例整体纠偏成功率。旧0.2.1的F16局部修复不混入0.3.0成绩。

## 系统与对照

主Agent和核对均使用DeepSeek官方deepseek-flash，开启thinking、高推理等级，单轮输出上限16384 token含思考。每8次成功主输出触发检查，成功包括工具调用输出。复用原始主请求前缀和工具配置，追加当前候选及可认证的完整用户要求；不额外mask、摘要、检索或调用Jev。reviewScope=current，verifyDefinitions=false。

核对分别判断目标、范围、方法，再形成最多一条有依据提醒。最多3次只读工具尝试、4轮生成、整次120秒、每工具15秒。只把最终提醒送入主Agent；辅助核验对话单独记录。不暂停任务等待人工批准。

真实定期对照从原第21轮结束状态分叉，继续原任务22–33；接入时计数为0。两组首请求与原始请求逐字节一致，初始文件与原生会话一致。有插件先跑、无插件后跑，各一次。所有提醒均核实进入后续实际主请求。该顺序及采样差异限制因果、成本及统计推断。

裁定使用单一非盲审阅者及原始CSV的确定性复算，没有独立人工复核。不执行主Agent产出的代码或pickle作为正确答案来源。只公开整理后的结论与哈希，不复制第三方数据、原始请求、工作区或私有推理；公开脚本可核算表中分数，不能独立重放全部原始实验。
